# Repository Guidelines

## Overview

Live dashboard for a WEG CMSW-IOL vibration sensor on a Siemens S7-1200
(ifm AL1306 IO-Link master). The PLC sends UDP to a Python bridge on the lab
PC, which publishes to HiveMQ Cloud; the React + TypeScript + Vite website
subscribes over WebSockets. Start with `docs/README.md`.

## Layout

| Path | Content |
|---|---|
| `src/model/` | Sensor facts: alarm bits, PQI bits, severity zones (`sensor.ts`); payload parsing (`messages.ts`) |
| `src/mqtt/` | Topics and the single broker connection (subscribe only) |
| `src/state/` | Store with the latest sample and the history |
| `src/sim/` | In-browser demo data |
| `src/components/`, `src/hooks/` | UI |
| `bridge/` | UDP → MQTT bridge (standard library only), fake PLC, lab PC kit (`make_kit.py`, `kit/`) |
| `docs/` | Sensor, TIA Portal setup, PLC sender, bridge, MQTT contract, deploy, lab checklist |

## Commands

- `npm install`: install dependencies.
- `npm run dev`: local dev server.
- `npm run build`: type-check and production build. Must pass before every commit.
- `python3 bridge/bridge.py --selftest`: check the broker connection.
- `python3 bridge/fake_plc.py`: fake PLC on 127.0.0.1:5010.
- `python3 bridge/make_kit.py`: build the lab PC kit into `bridge/dist/` (ignored by git).

## Code rules

- Code, comments and docs in English.
- The website is read-only: do not add MQTT publishing from the browser.
- Never commit broker passwords or hosts. `VITE_*` variables are public;
  real values go in `.env.local`, which is ignored.
- Do not commit vendor files (IODD, GSDML, TIA projects).
- Validate every incoming payload in `src/model/messages.ts`.
- The bridge stays standard-library only: the lab PC cannot `pip install`.
- Keep these in sync when they change:
  - The UDP packet layout in `docs/plc-udp-sender.md`, `bridge/bridge.py` and `bridge/fake_plc.py`.
  - Topics/payloads in `src/mqtt/topics.ts`, `src/model/messages.ts`, `bridge/bridge.py` and `docs/mqtt-contract.md`.
  - Alarm and PQI bits in `src/model/sensor.ts` and `docs/sensor-cmsw-iol.md`.
  - The demo rules in `src/sim/demo.ts` and `bridge/fake_plc.py`.
  - Addresses in `docs/tia-portal-setup.md`, `docs/sensor-cmsw-iol.md` and `bridge/kit/AI-CONTEXT.md`.
- Facts not yet verified on the real equipment are marked **[to check]** in the docs.

## Git workflow

- One branch per change, from `main`: `feat/...`, `fix/...`, `docs/...`,
  `refactor/...`, `chore/...`.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
  `type(scope): summary` in the imperative, lowercase, no trailing period.
  Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`.
  Scopes: `ui`, `mqtt`, `model`, `sim`, `bridge`, `docs`.
- No authorship attribution in commits or pull requests: no `Co-authored-by`,
  `Signed-off-by` or "generated by" lines.
- Merge to `main` through a pull request. The PR description says what
  changed, why, and how it was tested.
- Remote uses the personal SSH alias: `git@github-pessoal:Silvio347/inatel-accelerometer-dashboard.git`.
  Only the personal account (Silvio347) is used for this repository.
